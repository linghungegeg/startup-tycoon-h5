# 真实创业模拟经营 H5 网游完整开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从 0 开发一款竖版 H5 网游付费游戏，核心是现代真实创业模拟经营、文字事件决策、主线/支线任务、平台币商业化、VIP、排行榜、称号、多服和跨服。

**Architecture:** 前端采用竖版商业手游布局，参考《少年三国志》的顶部资源栏、中部主场景、左右悬浮入口和底部导航。后端负责所有经营结算、平台币、VIP、奖励、排行榜、任务和跨服数据，客户端只负责展示和交互。

**Tech Stack:** React + TypeScript + Vite, Node.js + NestJS, React Admin, MySQL, Redis, BullMQ, Prisma。

## 1. 产品定位

这是一款 H5 网游付费游戏，不是纯文字小说，也不是纯战斗游戏。玩家扮演创业公司创始人，从小团队起步，经历招人、接项目、做产品、管现金流、融资、贷款、负债、裁员、竞品竞争、行业风口、政策变化和经营危机，最终走向上市、并购、行业独角兽，或在破产重组后二次创业。

核心卖点：

- 真实创业，不只点升级。
- 文字事件以现代商业信息流呈现。
- 经营压力可翻盘，不轻易 Game Over。
- 平台币商业化、VIP、排行榜、称号完整联动。
- 多服与跨服提供长期竞争目标。

全量托管原则：

- 开发计划、玩法系统、交互体验、任务内容、活动运营、员工体系、经济系统、付费设计均由本计划统一托管。
- 所有新增系统必须先有设计文档、配置结构、验收标准和测试点，再进入实现。
- 详细设计拆分到独立文档，避免总计划过长并降低后续多会话遗漏风险。

配套设计文档：

- `docs/employee-design.md`：员工系统、虚构员工、员工事件、员工付费边界。
- `docs/monetization-design.md`：平台币、VIP、月卡、基金、通行证、礼包、顾问、保险和付费节奏。
- `docs/retention-design.md`：首日、3 日、7 日、14 日、30 日留存目标和主线完成后长期循环。
- `docs/activity-design.md`：赛季、限时活动、活动临时榜、活动通行证、活动商店、经营残局。

## 2. 竖版布局

固定采用《少年三国志》式竖版商业手游结构。

已确认界面方向采用“稳重运营后台 + 手游式玩家入口”方案：

- 玩家端必须先进入独立登录/注册界面，登录后再选区、选头像、命名和进入游戏主界面。
- 玩家端登录入口要像竖版 H5 手游启动页，突出游戏名、账号登录、进入游戏和区服流程，不做普通网页表单堆砌。
- Admin 必须先进入独立后台登录界面，登录后才能进入管理后台。
- Admin 登录后采用稳重运营后台结构：左侧菜单、顶部用户/操作栏、筛选区、表格/列表、分页、批量操作、二次确认和审计入口。
- Admin 不采用卡片模块化堆积作为主要信息结构；概览块只能作为辅助摘要，核心管理页面必须以表格、筛选、详情抽屉/弹窗和操作记录为主。
- 前台和后台都必须使用符合本地用户习惯的中文文案、按钮、错误提示和状态提示。

- 顶部：公司等级、现金、平台币、行动力、负债预警、经营提醒。
- 中部：公司办公室、联合办公空间、独立办公楼、城市商业区或上市公司总部。
- 中部状态：现金流、月收入、月支出、主线任务、待处理事件。
- 左侧入口：财务、融资、贷款。
- 右侧入口：活动、排行、商业、特权、通行证、专属经理。
- 底部导航：公司、员工、业务、市场、商会、背包。

### 2.1 主页入口归属规则

- 主页左右入口只放一级高频入口，不放具体系统子功能。
- 左侧固定承载高频经营主入口：财务、融资、贷款。
- 顶部资源栏只展示现金、平台币、声望、行动力和公司估值，不承担弹窗或页面跳转。
- 右侧固定承载运营活动、排行、商业商城、特权付费、赛季通行证和专属经理提醒入口：活动、排行、商业、特权、通行证、专属经理；右侧使用纵向紧凑入口，必须避开主线任务条和底部导航。
- 商业入口承载普通钱包/商城，集中展示余额、首充、礼包、猎头、保险和普通平台币商品。
- 特权入口承载月卡和成长基金；通行证入口承载赛季通行证购买、状态和奖励线索。
- 头像承载玩家身份和 VIP 创业权益入口；VIP 每日礼包可领或权益待处理时在头像处显示红点，不再占用右侧悬浮入口。
- 风险、合同、用工、财报和舆情提醒归入专属经理提醒流，不在主页左右入口拆成多个独立按钮。
- 邮件只表达系统邮件、奖励邮件和补偿邮件；真实邮件收发/补偿领取页完成前，不作为主页快捷入口。
- 底部导航承载长期主系统：公司、员工、业务、市场、商会、背包。
- 业务入口承载项目交付与产品研发两个标签；二者只合并前台入口，不合并后端系统、数据模型或结算逻辑。
- 背包承载道具、礼包、招募券、活动材料和补偿奖励；产品研发归业务，商战竞争和市场营销归市场；投资合作归融资；企业并购和扩建归公司或主线事件。
- 出门谈判归主线、事件或行动力内页，不做主页大占位。
- 主线任务条属于中部状态，只显示标题、进度和前往，不遮挡左右入口和底部导航。

### 2.2 前台 UI 风格基线

- 后续前台页面默认沿用当前主页 HTML 风格，不重新发明一套视觉语言。
- 统一使用当前主页的深色商务手游风格：深色背景、金色主强调、玻璃面板、圆角图标按钮、底部导航、左右悬浮入口、紧凑资源栏。
- 新增内页、弹窗、活动页、商城页、背包页、排行榜、任务页和事件页，必须优先复用当前主页已有组件形态：`glass-panel`、`btn-gold`、`resource-tag`、顶部资源栏、底部导航、原生 SVG 图标风格。
- 主页内触发的财务、知识/合规支线和规则说明统一使用全覆盖内页；后续不再新增半屏弹窗或居中浮层承载核心经营信息。
- 员工、项目、产品、市场、融资、贷款、任务、专属经理等主系统页统一使用全覆盖内页壳，内部页头、摘要、列表、详情和 CTA 必须向财务、活动、商业等 native 页面风格收敛。
- 不允许为单个功能临时引入不一致的配色、字体、按钮形态、卡片圆角、阴影、营销页式 hero 或普通网页后台风格。
- 如果外部 AI 产出 HTML 设计稿，必须先对照当前主页风格做收敛：保留可用布局和动效，配色、按钮、入口密度、面板质感必须向主页基线靠齐。
- 只有登录/注册、选角、强底图活动页这类有独立底图的页面，可以在不破坏整体游戏气质的前提下做局部差异。

文字事件不以大段小说呈现，而是通过员工私信、客户邮件、投资人聊天、银行提醒、商业新闻、财报预警、会议纪要、合同审批和舆情热搜进入。

## 3. 核心系统设计

### 3.1 主线任务

主线任务负责推进公司阶段、解锁系统和承接 7 日体验。

- 草创阶段：注册公司、选择赛道、招第一名员工、接第一单。
- 生存阶段：完成 3 个项目、现金流转正、查看首次财报。
- 产品阶段：立项 MVP、上线第一个产品、获得第一批用户。
- 资本阶段：申请贷款、完成融资或选择稳健盈利路线。
- 竞争阶段：遭遇竞品、处理价格战、员工被挖、舆情事件。
- 危机阶段：现金流断裂、负债过高、融资失败、债务重组。
- 扩张阶段：进入新城市、新赛道、建立商会合作。
- 成熟阶段：上市、并购、跨服创业大赛、行业第一。

### 3.2 每日任务

每日任务用于留存和轻量循环。

- 登录。
- 完成项目。
- 培训员工。
- 处理事件。
- 查看财报。
- 领取经营收益。
- 参与活动。
- 使用一次市场分析或风险预警。

每日任务按服务器日刷新，奖励不可重复领取。

### 3.3 支线任务

支线按真实商业关系展开。

- 员工线：核心员工成长、离职、加薪、股权激励、被竞品挖角。
- 客户线：大客户压价、延期付款、合同纠纷、长期合作。
- 投资人线：估值谈判、对赌协议、董事会压力、融资失败。
- 银行线：贷款审批、信用评级、逾期催收、债务重组。
- 产品线：MVP、爆款增长、技术债、用户流失、重构。
- 竞品线：价格战、抄袭、挖人、舆论战、专利诉讼。
- 合规线：税务、劳动仲裁、数据合规、广告合规。
- 创始人线：声望、人脉、抗压、行业大会、媒体采访。

### 3.4 公司经营

核心指标：

- 现金。
- 月收入。
- 月支出。
- 净现金流。
- 公司估值。
- 股权比例。
- 负债总额。
- 负债率。
- 信用评级。
- 品牌声誉。
- 员工满意度。
- 客户满意度。
- 市场份额。

财务报表：

- 现金流表。
- 利润表。
- 资产负债表。
- 月度经营报告。

现金不足时进入危机状态，不直接结束游戏。

员工字段：

- 头像、职业徽章、岗位、职级、稀有度。
- 技术、销售、运营、管理、创意、财务、法务。
- 薪资、压力、忠诚度、成长潜力、离职风险。

员工操作：

- 招募。
- 培训。
- 晋升。
- 任命。
- 裁员。
- 股权激励。

职级：

- 实习生。
- 初级。
- 中级。
- 高级。
- 专家。
- 总监。
- 合伙人。

### 3.6 项目系统

项目类型：

- 外包开发。
- 企业咨询。
- SaaS 定制。
- 营销增长。
- 数据分析。
- AI 自动化方案。

项目有周期、预算、风险、成功率、员工分配、延期、失败、结算和客户满意度。项目结算必须幂等，不能重复发奖。

### 3.7 产品生命周期

产品阶段：

- 立项。
- MVP。
- 内测。
- 上线。
- 增长期。
- 成熟期。
- 衰退期。
- 重构。
- 关闭。

产品指标：

- 用户数。
- 留存率。
- 付费率。
- 获客成本。
- 服务器成本。
- 口碑。
- 技术债。

产品能产生长期收入，但增长会带来服务器、客服、合规和技术债压力。

### 3.8 贷款、融资与负债

贷款类型：

- 短期周转贷。
- 银行经营贷。
- 设备贷款。
- 高息应急贷。
- 政策扶持贷款。

融资轮次：

- 种子轮。
- 天使轮。
- A 轮。
- B 轮。
- C 轮。
- IPO。
- 并购。

负债后路线：

- 正常还款。
- 提前还款。
- 借新还旧。
- 裁员降本。
- 出售资产。
- 引入融资。
- 债务重组。
- 破产保护剧情线。

融资获得现金但稀释股权；贷款不稀释股权但增加负债和还款压力。

### 3.9 市场竞争与赛道差异

创业赛道：

- AI Agent 企业服务。
- 机器人/具身智能。
- 低空经济。
- 跨境 SaaS。
- 直播电商工具。
- 新能源运营服务。
- 银发经济服务。

竞品行为：

- 价格战。
- 抢客户。
- 挖员工。
- 舆论战。
- 专利诉讼。
- 抢融资。
- 产品抄袭。

不同赛道必须有不同成本结构、事件、政策风险、人才压力和增长路径。

### 3.10 现代化文字事件

事件入口：

- 员工私信。
- 客户邮件。
- 投资人聊天。
- 银行还款提醒。
- 商业新闻。
- 财报预警。
- 会议纪要。
- 合同审批。
- 舆情热搜。

每个事件提供 2-4 个决策卡，展示收益、成本、风险、影响指标和后续可能事件。选择结果必须落库，并能推进主线、支线或后续事件链。

### 3.11 平台币与商城

第一版主要以平台币支付为主，外部支付接口只做预留。

规则：

- 游戏内商品统一消耗平台币。
- 平台币余额只以后端为准。
- 平台币可由 Admin 后台发放、扣减、修正。
- 平台币变更必须写流水。
- 平台币购买商品必须在同一事务内完成扣减和发货。
- 平台币不足时购买失败且不发货。
- 重复请求不能重复扣币或重复发货。
- 外部支付订单、回调、验签、发货、补单流程预留接口和数据模型，但不作为第一版强依赖。

平台币来源：

- 后台发放。
- 活动奖励。
- 系统补偿。
- 预留外部充值接口。

平台币消耗：

- 月卡。
- 成长基金。
- 通行证。
- 限时礼包。
- 猎头招募券。
- VIP 商店。
- 活动商店。
- 经营顾问、风险保险、加速券等道具。

### 3.12 VIP 系统

关键规则：

- 玩家在游戏内消耗平台币，计入 VIP 经验。
- VIP 经验按消耗平台币数量换算。
- 后台发放平台币不直接增加 VIP 经验。
- 后台可手动调整 VIP 等级或经验，但必须写审计日志。
- VIP 不直接消灭现金流、负债和经营判断，只提供便利、信息优势和轻量加成。

VIP 权益：

- 每日礼包。
- 行动力上限提高。
- 快速项目结算次数增加。
- 员工培训队列增加。
- 免费刷新招聘次数增加。
- 财报高级分析提示。
- 风险预警提前。
- 专属头像框。
- 专属称号。
- 办公室皮肤。
- VIP 商店折扣。
- 专属礼包购买权限。

### 3.13 排行榜系统

第一版排行榜必须收敛，避免榜单过多导致玩家看不懂重点、奖励难平衡、结算复杂度过高。

常驻本服榜：

- 公司估值榜。
- 净现金流榜。
- 产品增长榜。
- 商会榜。

常驻跨服榜：

- 跨服创业大赛榜。
- 跨服商会榜。

活动临时榜：

- AI Agent 风口榜。
- 低空经济增长榜。
- 现金流挑战榜。
- 融资路演榜。
- 产品爆发榜。
- 合规经营挑战榜。
- 知识达人榜。

排行榜入口只显示本服、跨服、活动三类。活动榜只在活动开启时出现，活动结束后隐藏入口，但奖励、称号和成就记录保留。

排行榜奖励通过邮件发放，必须幂等。跨服榜按开服时间和活跃度分池，避免老服碾压新服。

### 3.14 称号系统

称号来源：

- 主线进度。
- 支线成就。
- 排行榜名次。
- 赛季活动。
- VIP 等级。
- 特殊经营结果。

称号类型：

- 成长称号：初创老板、连续创业者、行业新星。
- 财务称号：现金流大师、负债猎手、稳健经营者。
- 融资称号：天使宠儿、资本新贵、独角兽创始人。
- 产品称号：爆款制造机、技术理想派、增长黑客。
- 风险称号：绝境翻盘者、债务重组专家。
- 排名称号：本服首富、跨服独角兽、赛季冠军。
- VIP 称号：尊享会员、战略投资人。

称号可展示在头像、排行榜、商会、聊天和玩家资料。称号只提供轻量加成，同时只能装备 1 个主称号，避免属性堆叠失控。

### 3.15 成就系统

成就系统记录玩家创业履历，作为长期收集、荣誉反馈和知识解锁入口。

成就类型：

- 成长成就：完成第一单、现金流转正、公司估值破千万、上市。
- 财务成就：连续现金流为正、成功债务重组、负债率控制优秀。
- 员工成就：培养总监、留住被挖角员工、完成股权激励。
- 产品成就：上线 MVP、产品用户破万、完成技术债重构。
- 融资成就：完成天使轮、拒绝低估值融资、完成 IPO。
- 合规成就：正确处理劳动纠纷、完成数据合规整改、避免合同违约。
- 知识成就：解锁创业知识、完成合规问答、连续正确处理风险事件。
- 隐藏成就：绝境翻盘、破产重组成功、竞品暴雷后反超。

成就奖励可包含少量平台币、现金、行动力、经营资源、称号、头像框、办公室装饰和知识图鉴条目。成就奖励不直接增加 VIP 经验，VIP 经验仍以游戏内平台币消费为主。

### 3.16 创业知识库

创业知识库用于把真实经营中遇到的法律、合规、财务、用工和商业常识游戏化呈现。知识内容在开发和运营配置阶段通过联网检索官方或权威来源整理为游戏内科普卡，不依赖纯手写猜测。

知识分类：

- 公司设立与股权：注册资本、股东责任、股权稀释、董事会。
- 劳动用工：劳动合同、试用期、加班、裁员、经济补偿。
- 合同与客户：合同违约、付款周期、保密条款、竞业限制。
- 融资与投资：投资条款、对赌、优先清算权、股权激励。
- 贷款与债务：利息、逾期、担保、债务重组。
- 数据与隐私：用户授权、个人信息处理、数据泄露、跨境数据。
- 广告与营销：虚假宣传、广告合规、达人合作风险。
- 知识产权：商标、著作权、专利、软件代码归属。
- 税务与财务：发票、税负、成本入账、财报真实性。

知识内容来源策略：

- 优先检索全国人大网、政府网、国务院部门官网、国家市场监督管理总局、国家税务总局、国家网信办等官方来源。
- 可参考《公司法》《劳动合同法》《民法典合同编》《个人信息保护法》《广告法》《商标法》《著作权法》《税收征收管理法》等公开法律法规。
- 每条知识卡只做通俗科普和游戏风险提示，不直接复制大段法条。
- 每条知识卡必须标明来源名称、来源链接、采集日期和内容版本。
- 所有知识卡固定展示免责声明：仅作游戏科普，不构成法律建议。

首批知识内容种子：

- 公司设立与股权：公司设立、股东出资、股权稀释、董事会责任。来源优先使用全国人大网关于《公司法》修订说明和公开法律文本。
- 劳动用工：书面劳动合同、试用期、薪酬支付、解除劳动关系、经济补偿。来源优先使用全国人大网《劳动合同法》和《劳动法》公开文本。
- 合同与客户：合同订立、违约责任、付款延期、保密条款、合同解除。来源优先使用政府网/全国人大网《民法典》合同编相关公开内容。
- 数据与隐私：个人信息处理、用户同意、敏感个人信息、数据泄露通知。来源优先使用全国人大网《个人信息保护法》公开文本。
- 税务与财务：发票、纳税申报、税收征管、财务真实性。来源优先使用政府网《税收征收管理法》和国家税务总局公开说明。
- 广告与营销：虚假宣传、广告代言、直播/达人合作风险。来源优先使用政府网、市场监管部门公开法规和案例。
- 知识产权：商标、著作权、专利、软件代码归属。来源优先使用国家知识产权局、版权主管部门和公开法律文本。
- 贷款与债务：借款合同、担保、逾期、债务重组。来源优先使用《民法典》合同编及金融监管公开规则。

首批知识卡示例：

- “未签劳动合同的风险”：触发于员工入职后未规范签约事件，解释短期省事会提高劳动争议风险。
- “客户延期付款怎么办”：触发于大客户拖款事件，解释合同约定、催收、违约成本和客户关系取舍。
- “用户数据泄露危机”：触发于产品数据事故，解释及时补救、通知、整改和声誉影响。
- “融资为什么会稀释股权”：触发于天使轮/A 轮融资，解释现金增加与控制权下降的交换。
- “广告宣传不能乱承诺”：触发于营销投放事件，解释夸大宣传可能带来监管和声誉风险。
- “税务合规不是可选项”：触发于财务月报或税务稽查事件，解释现金流压力下也不能靠违规少缴税解决问题。

知识卡结构：

- 现实场景。
- 风险提示。
- 游戏选择。
- 知识解释。
- 来源标记。
- 游戏影响。
- 免责声明。

知识通过事件、任务、成就解锁。事件结算页显示“经营结果”“为什么会这样”“解锁知识”三段反馈。

## 4. 技术架构

### 4.1 前端

- React + TypeScript + Vite。
- 竖版 H5。
- 优先适配 375x667 到 430x932。
- 图片资源包括头像、员工、职业徽章、产品 Logo、投资机构 Logo、银行 Logo、办公场景。
- 前端只负责展示和交互，不做可信结算。

### 4.2 后端

- Node.js + NestJS。
- MySQL 存账号、角色、公司、员工、项目、产品、任务、事件、财务、平台币、VIP、订单预留、排行榜快照、称号、成就、知识库、商会、后台审计。
- Redis 存会话、排行榜缓存、限流、活动缓存、分布式锁。
- BullMQ 处理邮件、活动结算、跨服榜单、平台币相关异步审计、外部支付预留回调。
- ORM 使用 Prisma，后续阶段不再切换 ORM。

### 4.3 管理后台

- React Admin。
- 后台登录和权限角色。
- 玩家查询、公司财务查询、平台币查询、VIP 查询、称号查询、订单预留查询。
- 平台币发放、扣减、修正。
- VIP 调整。
- 商品、任务、事件、活动、排行榜、称号、成就、知识库配置。
- 邮件补偿、封禁/解封、区服管理、跨服分组。
- 服务器备份、数据库备份、静态资源备份和回滚依赖宝塔面板，不在游戏后台自建备份/回滚系统。
- 所有高风险操作写审计日志。

## 5. 主要 API

- Auth API：注册、登录、刷新 token。
- Server API：区服列表、推荐区服、选服。
- Profile API：头像、命名、创建公司。
- Company API：公司状态、财报、升级。
- Employee API：招募、培训、晋升、任命、裁员。
- Project API：接单、推进、结算。
- Product API：研发、上线、运营。
- Finance API：贷款、还款、融资、负债。
- Task API：主线、每日、支线、领奖。
- Event API：文字事件、选择、结算。
- Wallet API：平台币余额、流水。
- Shop API：商品、平台币购买、购买记录。
- VIP API：等级、经验、权益、礼包。
- Rank API：榜单、我的排名、奖励预览。
- Title API：称号、装备、过期状态。
- Achievement API：成就列表、完成状态、领取奖励、成就详情。
- Knowledge API：知识分类、知识条目、已解锁知识、知识点详情。
- Ops API：后台配置、玩家查询、平台币发放、VIP 调整、邮件补偿。
- Admin Achievement API：成就配置、奖励配置、完成条件配置。
- Admin Knowledge API：知识条目配置、来源链接、采集日期、内容版本、审核状态。
- Cross Server API：跨服排行、跨服活动、奖励结算。

## Phase 21：全功能开放、快节奏等级与随机经营任务

目标：

- 所有核心功能默认开放，不再用公司等级硬锁员工、业务、市场、财务、融资、贷款、商会、排行、商业、特权、通行证和背包入口。
- 公司等级改为玩家对比、首日冲榜、基金节点、主线推进、经验倍率和阶段奖励，等级上限固定为 80。
- 付费玩家通过经营周卡、成长基金和通行证经验倍率，目标 1 天满级；免费活跃玩家目标 2-3 天满级。
- 将主线从当前 8 个骨干任务扩展为 60-80 个短任务，覆盖公司启动、员工、项目、产品、财务、资本、市场、商会、赛季和跨服。
- 基于根目录原型 HTML 中的随机经营事件弹窗，建设正式随机经营任务系统，覆盖项目、员工、产品、财务、市场、商会、赛季和风险事件。
- 补全行动力、声望和 VIP15 体系：行动力代表创始人精力，声望代表品牌口碑，VIP 代表身份、便利和轻量经营效率。
- VIP 上限扩展到 VIP15，新号创建公司后永久赠送 VIP3；赠送写入 `vipExperience = 3000`，但 `totalSpent = 0`，不计入真实消费和付费转化。

设计规则：

- 等级不卖功能，不阻止玩家进入核心玩法；主线负责解释功能价值，等级负责奖励、对比和付费效率承接。
- 经验来源包括主线任务、每日任务、随机经营任务、项目/产品/员工/市场操作和赛季任务。
- 经验倍率采用中强方案：免费 1.0 倍，经营周卡 1.5 倍，周卡加成长基金 1.8 倍，周卡加成长基金加通行证最高 2.0 倍封顶。
- 倍率只影响公司经验，不放大现金、平台币和排行榜结算奖励，避免经济膨胀。
- 成长基金改为首日冲级基金加满级后深度基金，节点建议为 Lv.5、10、15、20、30、40、50、60、70、80。
- 满级后经验转为创业声望积分、赛季贡献或满级宝箱进度，避免满级玩家经验浪费。
- 行动力不限制进入功能页面，只限制高收益经营动作；基础上限 120，每 10 分钟恢复 10 点，离线恢复到上限。
- 行动力饮料普通购买每日限 3 次，每日经营礼包每日限 1 次；VIP 可提高上限和限购次数，但不得形成无限购买。
- 声望不作为普通消耗货币滥用，主要影响融资成功率、估值议价、市场竞争、商会贡献、排行榜展示和随机任务选项。
- VIP 权益不得直接清空负债、免除经营失败、直接提高排行榜名次或提供不可替代玩法。

随机经营任务规则：

- 在线每 3-8 分钟有概率触发一次；首次进入游戏前 2 分钟不弹，商城购买、领取奖励和通行证操作中不弹。
- 普通玩家每日最多 6 次，周卡/月卡玩家最多 9 次，通行证玩家额外获得赛季随机任务。
- 随机任务不是广告弹窗，必须是经营选择：标题 1 行、说明 2 行以内、2-3 个决策、明确消耗、风险和奖励。
- 随机任务可以消耗或使用行动力饮料、风险保险、市场情报、财务顾问卡、定向猎头函等道具改变结果。
- 可关闭的随机任务进入专属经理待办流，不强迫立即处理；高价值任务可显示倒计时，普通任务不制造焦虑。

商业承接：

- 经营周卡展示 1.5 倍公司经验、每日行动力、培养材料和风险保险。
- 成长基金展示等级节点奖励和经验倍率参与上限。
- 通行证展示赛季任务、额外随机赛季任务和经验倍率参与上限。
- 商城补充随机经营任务相关道具包，例如风险保险包、顾问卡包、员工培养包、市场情报包和行动力包。
- 付费推荐只在任务结果、道具不足或基金节点接近时出现，不在任务开始前硬弹购买。
- VIP3 作为开服基础权益强化首日福利感；VIP4-VIP15 承接周卡、成长基金、通行证、员工养成、商会、跨服、外观和长期身份付费。

验收标准：

- 新号进入后所有核心功能入口可打开。
- 完成主线和随机经营任务后，公司经验和等级快速增长。
- 周卡、成长基金、通行证经验倍率显示和计算正确，最高不超过 2 倍。
- 付费玩家在高活跃 1 天内可满级，免费活跃玩家 2-3 天可满级。
- 随机经营任务不会遮挡主页 HUD，不频繁打断首日任务。
- 满级后经验仍有明确去向。
- 新号 VIP 中心显示 VIP3，且 `vipExperience = 3000`、`totalSpent = 0`。
- VIP0-VIP15 等级阈值递增，平台币消费和通行证购买能从 VIP3 继续累加 VIP 经验。
- 行动力恢复、消耗、限购和溢出规则以后端服务器时间为准，不能依赖前端计时。

## 12. 创业知识内容规则

- 知识内容在开发和运营配置时必须联网检索，不凭空编写关键法律常识。
- 优先使用全国人大网、政府网、国务院部门官网、国家市场监督管理总局、国家税务总局、国家网信办等官方来源。
- 可使用《公司法》《劳动合同法》《民法典合同编》《个人信息保护法》《广告法》《商标法》《著作权法》《税收征收管理法》等作为知识来源范围。
- 每条知识卡必须记录来源名称、来源链接、采集日期、内容版本和审核状态。
- 知识卡只做游戏科普和风险提示，不构成现实法律建议。
- 禁止复制大段法条进游戏正文，正文应转写成短句、场景化、可扫读的解释。
- 事件结算页必须把知识点和经营结果绑定，让玩家理解“为什么这个选择会带来这个风险或收益”。

## 13. 关键假设

- 布局固定采用《少年三国志》式竖版商业手游结构。
- 已确认采用“稳重运营后台 + 手游式玩家入口”方案：前台和 Admin 都必须独立登录后才能进入对应系统，Admin 采用稳重运营后台结构，不采用卡片模块堆积。
- 游戏核心是 H5 + 文字事件 + 真实模拟经营。
- 主数据库使用 MySQL。
- Redis 用于缓存、排行榜、锁、会话和活动状态。
- 注册登录、选区服、选头像、命名、创建公司是正式流程。
- 主线、支线、每日任务、事件、平台币、VIP、排行榜、称号、成就、创业知识库都纳入第一版完整设计。
- 主线完成后通过赛季、限时活动、经营残局、商会、跨服、成就、知识库和外观收集维持长期留存。
- 第一版主要以平台币商业化为主，外部支付接口只预留。
- 平台币消费计入 VIP 经验。
- 后台发放平台币不默认计入 VIP 经验。
- 常驻排行榜保持少而清晰，活动榜只在活动开启时展示。
- 备份和回滚依赖宝塔面板，不在项目中自建。
