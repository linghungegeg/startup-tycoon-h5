# 游戏 UI 复刻止损流程

## 目标

本流程用于批量复刻游戏 UI 页面，避免单张图反复手调。后续所有底图叠层页面必须先通过静态视觉复刻，再进入动态数据和素材动态化。

## 当前稳定点

- 跨服主页当前标记为中间稿，不作为最终复刻范式。
- 当前代码可作为可运行稳定点保留，但不得继续在该稿上追加视觉试错。
- 后续跨服或其他页面重做时，必须从本流程的静态复刻阶段重新开始。

## 三阶段流程

### 1. 静态复刻

- 只确定一张最终视觉参考图作为唯一主准。
- 使用最终参考图或干净底图作为主视觉底板。
- 只保留返回、主按钮、次按钮等透明热区。
- 不恢复头像、员工卡、排名、次数等动态层。
- 浏览器截图第一眼不像参考图时，不进入下一阶段。

### 2. 最小动态化

- 只恢复必须变化的数据，例如排名、次数、金额、状态数字。
- 每恢复一个动态文本层，必须截图验收一次。
- 动态文本必须有 `x/y/w/h/maxWidth/baseline`，不得只给起点坐标。
- 文本超宽时必须收缩、截断或隐藏，不能覆盖按钮和相邻内容。

### 3. 素材动态化

- 最后恢复头像、人物、员工卡、装备图等素材层。
- 每个素材层必须有目标矩形、裁切规则和回退素材。
- 素材裁切没有明确规则时，停在静态或最小动态阶段，不继续靠猜。

## 权威输入规则

每张图开工前必须固定以下输入：

- 最终视觉参考图。
- 干净底图或静态底板。
- 必须保留的点击热区。
- 必须动态的数据清单。

同一阶段只能有一个主准。HTML 坐标、PNG 参考、新 JSON、浏览器截图不能同时作为主准；非主准只能用于辅助定位。

## 验收闸门

- 静态复刻未通过，不进入动态化。
- 动态层每增加一层，必须保留一张浏览器截图用于人工验收。
- 测试通过只证明结构没坏，不能替代视觉验收。
- 单张页面静态复刻超过半天仍不像，必须暂停并检查输入图、底图和热区定义。
- 如果连续两轮调整没有产生可见改进，停止补丁，输出问题清单。

## 每页最低测试

- 一个结构测试：确认没有可见 DOM 文字层和图片层乱叠。
- 一个热区 smoke test：确认返回、主按钮、次按钮可点击。
- 一个截图产物：用于人工对照参考图验收。

## 提交规则

- 临时截图和像素对比图默认不提交。
- 每次提交只包含当前阶段需要的文件。
- 未通过静态复刻的页面，文档必须明确标记为中间稿或失败稿。
