# 上线准备检查清单

## 阶段边界

本阶段完成仓库内商业测试上线准备：生产配置检查、上线流程、宝塔面板配置指引、灰度发布、压测口径、安全检查、客服处理和开服流程文档。当前不执行真实服务器部署，不接入真实外部支付回调，不在游戏项目内自建服务器或数据库备份系统。

备份、数据库备份和回滚按开发计划交由宝塔面板和服务器运维流程负责。

## Phase 27 质量收口补充

Phase 27 在 Phase 18 基础上完成商业化稳定、经济巡检、玩家主流程、Admin 主流程和生产前质量回归。当前本地商业测试上线前必须额外确认：

- API：`/health` 返回 `ok`，`/readiness` 在 MySQL/Redis 均配置时返回 `ready`。
- 鉴权：玩家与 Admin 无 token 访问受保护接口返回 `401 UNAUTHORIZED`。
- 错误码：未知路由返回 `404 NOT_FOUND`，鉴权连续失败触发 `429 RATE_LIMITED`。
- 审计：Admin 高风险操作继续通过审计日志追溯，未登录不能读取 `/admin/audit-logs`。
- 前台：主页 HUD、底部导航、活动、Rank、商业、通行证、背包、专属经理入口可见。
- Admin：顶部显示 `Phase 27 质量收口`，主菜单和只读巡检区域可访问。

## 生产环境配置

上线前必须确认部署环境只通过环境变量或宝塔面板配置注入敏感信息，不写入仓库：

| 配置项 | 用途 | 上线要求 |
| --- | --- | --- |
| `NODE_ENV` | 运行环境 | 设置为 `production` |
| `HOST` / `PORT` | API 监听地址 | 由宝塔反向代理或进程管理统一配置 |
| `DATABASE_URL` | MySQL 连接 | 指向生产库账号，禁止提交到仓库 |
| `REDIS_URL` | Redis 连接 | 指向开启持久化的 Redis 实例 |
| Admin 登录配置 | 运营后台登录 | 使用生产专用强密码，禁止复用本地测试值 |

API 提供 `GET /readiness` 作为上线前依赖检查入口。当前检查 MySQL 与 Redis 是否已配置；返回 `ready` 才允许进入灰度放量，返回 `blocked` 时必须先处理缺失依赖。

## 静态资源与 CDN

- 玩家端构建产物：`apps/client/dist`。
- 运营后台构建产物：`apps/admin/dist`。
- `index.html` 不设置长期缓存，避免灰度或回滚时入口文件滞后。
- 带 hash 的 `assets/*` 可设置长期缓存和 immutable。
- CDN 回源应指向当前发布目录；回滚时通过宝塔站点根目录或发布目录软切换完成。
- 前端 API 地址通过部署环境配置或反向代理保持同源，避免在构建产物里写死生产密钥。

## 宝塔面板部署配置

推荐按“前台站点、后台站点、API 服务、MySQL、Redis”拆分管理：

| 项目 | 宝塔配置点 | 检查标准 |
| --- | --- | --- |
| 前台站点 | 站点根目录指向 `apps/client/dist` 发布目录 | 刷新任意前台路由不 404 |
| 后台站点 | 站点根目录指向 `apps/admin/dist` 发布目录 | 未登录不能进入后台页面 |
| API 服务 | Node 项目或进程守护运行 API | `/health` 与 `/readiness` 可访问 |
| 反向代理 | `/api` 或独立 API 域名转发到 API 端口 | 请求头、超时、上传大小配置明确 |
| MySQL | 生产库、专用账号、最小权限 | 连接串仅存在部署环境 |
| Redis | 开启持久化与内存限制 | 重启后会话和缓存策略符合预期 |
| 定时任务 | 宝塔计划任务 | 数据库备份、日志轮转、发布前快照 |

服务器备份、数据库备份和回滚不在游戏后台重复建设，由宝塔面板能力和运维流程执行。

## Redis 持久化策略

- 商业测试前必须开启 Redis AOF 或 RDB 持久化，优先选择 AOF everysec。
- 设置合理 `maxmemory` 和淘汰策略，避免缓存膨胀影响主流程。
- API 启动后通过 `/readiness` 确认 Redis 已配置。
- 重启 Redis 后必须重新验证注册登录、进入游戏、排行榜、活动缓存和限流行为。

## 灰度发布流程

1. 在预发布环境部署同版本 API、前台和后台构建产物。
2. 执行数据库生成、推送、种子和全量类型检查、测试、lint、build。
3. 访问 `/health` 和 `/readiness`，确认依赖状态。
4. 使用少量测试账号验证注册登录、创建角色、进入主页、平台币、VIP、排行榜、商城、后台查询。
5. 开启小流量灰度，监控错误日志、接口耗时、平台币异常告警和外部支付预留告警。
6. 放量前保留上一稳定发布目录和宝塔备份点。
7. 灰度异常时停止放量，切回上一发布目录并保留错误 traceId。

## 压测口径

压测不替代功能测试。压测前必须使用隔离测试服和测试数据库，禁止压生产正式玩家数据。

| 场景 | 目标接口/流程 | 通过标准 |
| --- | --- | --- |
| 注册登录 | `/auth/register`、`/auth/login` | 无 5xx，限流按策略生效 |
| 角色恢复 | `/profiles`、主页加载接口 | P95 延迟满足商业测试目标 |
| 商城购买 | 钱包、商城购买、平台币流水 | 幂等请求不重复扣币或发货 |
| VIP 礼包 | VIP 查询、领取、经验变动 | 重复领取被拦截 |
| 排行榜 | 榜单查询、结算 | 结算幂等，查询稳定 |
| 后台看板 | `/admin/analytics` | 慢接口和错误可追踪 |

压测报告至少记录：测试时间、版本提交号、环境规格、并发模型、核心接口 P50/P95/P99、错误率、数据库与 Redis 资源占用、发现的问题和处理结论。

## 安全检查

- 客户端不可信，现金、平台币、VIP、奖励、排行榜结算均以后端为准。
- 登录、注册和后台登录已有基础防刷限流；上线前需要结合 Nginx 或宝塔防火墙继续限制异常来源。
- 平台币变更必须写流水，高风险后台操作必须有 Admin Token 校验和审计日志。
- 商品购买必须保持余额校验、扣减、发货在同一事务中完成，并验证幂等键。
- 外部支付当前仅为预留订单，不接真实回调；未完成验签、回调幂等和补单审核前，不允许暴露公开发货回调。
- 外部支付预留接口必须校验商品金额与平台币数量，不能信任前端传入的任意金额。
- 生产 CORS 与反向代理来源应在上线配置中收敛到正式域名。

## 客服处理流程

| 问题类型 | 处理入口 | 必查证据 | 处理动作 |
| --- | --- | --- | --- |
| 平台币余额争议 | 后台玩家查询、钱包流水 | 玩家 ID、流水来源、traceId | 核对后补偿或修正，写审计 |
| 商品未到账 | 购买记录、钱包流水、背包/权益 | 幂等键、订单时间、扣币流水 | 补发邮件或权益，禁止重复发货 |
| VIP 异常 | VIP 查询、平台币消费流水 | VIP 经验、等级、领取记录 | 后台调整并写审计 |
| 充值预留异常 | 外部支付预留订单 | 商品 ID、金额、平台币数量 | 未接真实支付前只做订单核对，不自动发货 |
| 封禁/解封 | 后台玩家状态与审计 | 操作人、原因、时间 | 二次确认后操作 |
| 系统补偿 | 邮件补偿 | 影响范围、补偿理由 | 批量或单人补偿，记录原因 |

客服回复必须保留玩家 ID、服务器、问题时间、traceId 或订单号，避免只按昵称处理。

## 开服流程

1. 确认本次发布提交号、数据库状态、宝塔备份点和回滚目录。
2. 执行 API、前台、后台构建和部署。
3. 执行数据库结构同步和正式种子数据检查。
4. 检查 `/health`、`/readiness`、前台首页、后台登录页。
5. 使用测试账号完成注册、登录、创建角色、进入主页。
6. 验证平台币发放、商城购买、VIP 查询、排行榜、成就、知识库、商会、后台玩家查询和数据看板。
7. 开启灰度测试账号或小流量入口。
8. 观察错误日志、慢接口、平台币异常告警、外部支付预留告警。
9. 放量后保留客服值守和回滚负责人。

## Phase 18 最小代码检查点

- `GET /readiness`：上线前暴露依赖配置状态。
- Auth 防刷：连续异常登录、注册或后台登录请求超过窗口限制后返回 `429`。
- 外部支付预留：带商品 ID 的订单必须匹配服务端商品金额与平台币数量。
- 当前阶段只增加上线安全护栏，不改变既有经营、平台币、VIP 或前台玩法流程。
