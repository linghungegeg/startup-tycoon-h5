# 底图叠层 UI 开发规范

## 1. 适用范围

本规范适用于所有“底图承载视觉、代码叠加文字、按钮、输入框、热区”的前台页面，包括但不限于登录/注册页、选角页、主页、活动页、弹窗和运营入口。

这类页面的验收标准以底图上的真实外部框、按钮框、图标和装饰文字为准，不以 HTML 控件默认位置为准。

## 2. 强制工作流

开发或调整底图叠层页面时必须按以下顺序执行：

1. 确认底图文件、原始尺寸和画布比例，例如 `941 / 1672`。
2. 先标记底图上的外部框区域，再写 CSS；禁止直接用小文字槽反复手调。
3. 每个可交互区域先建立覆盖底图外部框的叠层盒子，再在盒子内部处理文字、输入、图标和点击热区。
4. 每次只改一个明确变量，例如只改账号输入框纵向位置，或只改勾选框文字间距。
5. 改完必须用 Browser Use 刷新当前页面，截图检查实际渲染。
6. 视觉稳定后再运行本阶段要求的 `typecheck`、`lint`、`build`。
7. 作为稳定点提交前，确认临时截图、像素对比图、调试标记和未确认素材没有进入提交。

## 3. 坐标与布局规则

- 画布必须使用底图原始比例作为唯一定位基准。
- CSS 坐标优先使用百分比，百分比来源必须能追溯到底图实际框体，而不是当前浏览器截图里的临时观感。
- 文字、输入框、密码圆点和勾选状态都必须先落在对应底图外部框内，再做视觉居中。
- 输入框文本起点以底图图标右侧内容区为准，不居中到整条输入框。
- 带装饰文字的区域要避开底图已有装饰，例如区服名称不能覆盖“选区”字样。
- 点击热区可以大于可见文字，但不得越过相邻按钮或输入区域。
- 勾选框如底图已包含方框，只隐藏原生 checkbox 视觉；代码只负责点击状态、勾号和可访问性。

### 3.1 主页入口叠层规则

- 主页左右入口按底图预留热区建盒，不因临时功能增加扩大热区。
- 主线任务条必须避开左右入口和底部导航，宽度和高度按底图任务外框确定。
- 左侧经营入口只放高频独立主入口，例如财务、融资、贷款；风险、合同、用工、财报和舆情提醒归入专属经理提醒流。
- 顶部资源栏只展示现金、平台币、声望、行动力和公司估值，不做弹窗或页面跳转入口。
- 右侧运营入口固定为活动、排行、商业、特权、通行证和专属经理提醒；头像承载身份和 VIP 权益。
- 右侧 6 个入口采用纵向紧凑布局，按钮尺寸和间距必须避开顶部资源栏、主线任务条和底部导航。
- 商业入口归普通钱包/商城，承载首充、礼包、猎头、保险和普通平台币商品；特权入口承载月卡和成长基金；通行证入口承载赛季通行证购买、状态和奖励线索。邮件只用于真实系统邮件、奖励邮件和补偿邮件，不承载风险/合同/财报事件。
- 经营子功能进入对应内页，不挤占右侧运营入口，也不把同一事件系统拆成多个主页按钮。
- 后续换成做图 UI 时，代码只填充对应热区，不重新定义入口归属。

### 3.2 主页 HTML 风格复用规则

- 当前主页 HTML 风格是前台游戏 UI 的默认基线。
- 后续页面优先复用主页的容器、按钮、图标、资源条、玻璃面板、金色 CTA、底部导航和左右入口节奏。底部导航固定为公司、员工、业务、市场、商会、背包；业务入口内部分为项目交付和产品研发，背包作为长期资产入口保留在底部导航。
- 背包页必须展示真实道具资产，不再使用静态占位格；任务、商城、特权、通行证和活动商店发放的道具都应能在背包中看到名称、数量、用途和来源提示。
- 特权页展示周卡、月卡、7日基金、成长基金和 VIP 权益预期；通行证页展示赛季任务线、免费/付费奖励线和购买状态；商业页只展示普通商城商品。
- 新增 UI 先判断是否属于“内页填充”还是“底图叠层”：内页填充沿用 HTML 风格；底图叠层按底图外框定位，但控件质感仍尽量贴近主页。
- 主页内触发的财务、知识/合规支线、规则说明等经营面板默认使用全覆盖内页，不再新增半屏弹窗或居中浮层，避免遮挡主线任务条、底部导航和左右入口。
- 员工、业务（项目交付/产品研发）、市场、融资、贷款、任务、专属经理等主系统页也必须使用全覆盖内页壳，页头控制、摘要卡、列表卡、详情卡和主 CTA 需与财务、活动、商业等 native 页面保持同一深色玻璃与金色强调风格。
- 不允许在同一阶段混用多套明显不同的视觉系统。
- 如果必须偏离主页风格，阶段总结必须写明原因、影响范围和回归检查结果。

### 3.3 随机经营任务弹窗规则

- 随机经营任务可以使用居中弹窗，但它必须是短决策弹窗，不承载主系统页面。
- 弹窗必须沿用主页深色商务手游基线：深色遮罩、玻璃面板、金色主 CTA、原生 SVG 图标风格。
- 内容限制为标题 1 行、说明 2 行以内、2-3 个选择按钮、明确消耗/风险/奖励。
- 弹窗必须可关闭；关闭后进入专属经理待办，不强迫玩家立即处理。
- 随机任务不是广告弹窗，不能在任务开始前强制购买商品。
- 付费推荐只允许出现在任务结果、道具不足或基金节点接近时。
- 首次进入游戏前 2 分钟不触发随机任务；商城购买、领奖、通行证操作中不触发。
- 弹窗不得连续叠加，也不得遮挡正在进行的支付、登录、注册、选服和创建公司流程。
- 高价值随机任务可显示倒计时，普通随机任务不制造倒计时焦虑。

### 3.4 VIP 与行动力 HUD 展示规则

- 新号永久赠送 VIP3，头像区域可直接展示 VIP3 起步状态；VIP 入口仍归头像，不恢复为右侧运营入口。
- VIP 页首屏只展示当前等级、下一等级进度、今日礼包、当前核心权益和一个进入全部权益的入口。
- `全部 VIP 权益` 默认折叠或进入二级列表，不默认铺满首屏，避免移动端挤压主 CTA、领奖状态和等级进度。
- VIP 页必须明确区分赠送 VIP3 与真实消费成长：`vipExperience = 3000`、`totalSpent = 0` 属于开服赠送，不计入真实消费和付费转化。
- 行动力不足提示使用轻量底部条、资源位提示或小型确认弹窗，不遮挡主页 HUD、主线任务条、左右入口和底部导航。
- 行动力代表创始人精力，行动力提示应优先给出等待恢复、使用道具、降低消耗选项，再展示周卡、月卡或礼包建议。
- 声望代表品牌口碑，声望变化提示只做结果反馈或详情说明，不作为强弹付费入口。
- VIP 权益展示不得使用连续弹窗，也不得在玩家处理随机任务、支付、领奖、通行证或创建公司流程时覆盖关键操作。

## 4. 技能使用规则

所有开发阶段默认使用四插件；涉及底图叠层、主页、HUD、活动页、弹窗、运营入口时必须额外按本规范进行视觉验收。

- `Superpowers`：每个阶段开始前用于阶段计划、成功标准、最小改动范围、单变量实验、稳定点管理和提交前自检。
- `Browser Use`：每个阶段完成后用于本地页面刷新、截图、交互验证和视觉回归检查；底图叠层页面必须使用。
- `Build Web Apps`：每个涉及前端、页面、入口、弹窗、布局或视觉的阶段，用于布局一致性、视觉层级、移动端适配、控件排版和最终视觉验收。
- `Game Studio`：每个涉及游戏主页、HUD、主场景、玩法入口、任务/奖励展示或沉浸感的阶段，用于游戏界面体验、HUD/场景动线、玩法入口和沉浸感验收。

插件可用时必须使用。插件不可用或无法连接时，必须记录原因、降级验证方式和未覆盖风险；不可用不阻塞提交，但必须用 `Browser Use + Build Web Apps` 补齐可视检查，并在阶段总结里说明风险。

技能不是扩展范围的理由。使用技能只服务当前阶段目标，不允许借机重构无关模块或新增未要求功能。

## 5. 验收清单

底图叠层页面完成前必须检查：

- 375x667、当前浏览器视口、接近 430x932 的竖屏尺寸下，关键内容不溢出、不遮挡。
- 文本没有压到底图框线、贴图标、覆盖底图装饰字或偏离视觉中心。
- 输入框、密码圆点、勾选框、按钮文字与底图外部框上下间隔合理。
- 所有按钮和热区能点击，且不会误触相邻区域。
- 页面保留正式中文产品文案，没有测试文案、调试文案、临时英文或占位文案。
- 新增页面与主页截图对比，确认配色、按钮、图标、面板、文字层级一致。
- 使用 `Build Web Apps + Game Studio` 检查新增 UI 是否破坏主页已固定的游戏 HUD 感和操作密度。
- 随机经营任务弹窗出现、关闭、进入待办和结果反馈均不遮挡主页 HUD、底部导航和左右入口。
- 浏览器截图与底图参照一致；如果仍有偏差，必须写明偏差、原因和下一步单变量调整。

## 6. 临时资产与提交规则

- 调试截图、像素差异图、放大裁剪图可以用于排查，但默认不得提交。
- 根目录临时素材不得因“顺手清理”被删除或提交，除非用户明确要求。
- 每次提交只包含本次阶段目标直接需要的文件。
- 若需要长期保存坐标说明，应写入文档或代码注释；不要依赖临时图片文件作为唯一依据。
